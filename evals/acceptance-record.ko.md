# 평가 기준 기록

실제 비교에 사용하는 양식입니다. 후보를 평가하기 전에 1~3절을 먼저 작성합니다. 공개 가능한 증거를 연결하고 없으면 미확인으로 남깁니다. 비공개 업무 원문을 저장소에 복사하지 않습니다. 별도 승인 단계를 추가하는 양식은 아닙니다.

## 1. 승인한 결과
- 결과물과 버전:
- 누가 언제 승인했는지와 근거 (또는 승인 대기):
- 승인 범위: 내용, 배치, 동작, 업무 범위:

## 2. 유지할 요구사항
| ID | 요구사항과 출처 | 검사 또는 사람이 판단할 질문 | 기존 버전 | 후보 |
| --- | --- | --- | --- | --- |
| R1 | | | 미검증 | 미검증 |

최근 피드백에 없는 조건과 드물게 쓰는 조건도 포함합니다. 기준 변경을 승인받았다면 별도 기록합니다. 특정 결함에 대한 피드백으로 기존 승인 기준을 대체하지 않습니다.

## 3. 이번 변경 목표
- 관찰된 문제와 실행 증거:
- 제안한 부분 수정 또는 전체 재구성이 필요한 이유:
- 기대 효과와 측정 방법:

## 4. 비교 기록
- 대상·Skilloom 커밋, 모델·클라이언트·도구 버전:
- 문제 사례, 기존 성공 사례, 후보 설계에 쓰지 않은 입력:
- 버전별 새 컨텍스트·초기 상태와 조건 차이:
- 실제 결과물, diff, 실행 명령, 결과, 반복 횟수:
- 사람에게 확인할 질문과 답, 남은 판단:

모델의 좋은 평가를 사용자 승인으로 기록하지 않습니다. 과거 결과와 비교하거나 결과물이 없으면 한계로 적습니다.

## 5. 결정
채택 / 기존 버전 유지 / 후보 별도 보관 / 수정하지 않음 중 선택합니다.
- 요구사항별 판단 근거와 측정한 효과:
- 실패하거나 검사하지 못한 기준:
- 복구 위치와 활성 버전:

구조 정리와 측정된 행동 개선은 다른 주장입니다. 필요한 판단이 없으면 기존 버전을 유지하고 빠진 근거를 밝힙니다.
