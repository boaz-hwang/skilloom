# 줄 수보다 먼저 요구사항을 확인합니다

[English](README.md)

구조 정리와 결과물 검사를 설명하기 위해 작성한 가상 예제입니다. 입력·지침·출력 모두 이 저장소를 위해 작성했습니다. 두 지침으로 코딩 에이전트를 실행하지 않았으며, 사람의 승인이나 성능 개선을 주장하지 않습니다. 기준 결과물이 승인된 결과물의 역할을 대신해 비공개 자료 없이 흐름을 확인하게 합니다.

## 전체 흐름

1. [기준 입력](reference.csv)과 [기준 결과물](reference-result.json)을 확인합니다.
2. 후보를 판단하기 전에 아래 요구사항을 고정합니다.
3. [기존 지침](before.md), [후보 지침](after.md), [diff](change.diff)를 비교합니다.
4. [새 입력](new-input.csv), [기존 출력 예시](baseline-output.json), [후보 출력 예시](candidate-output.json)를 봅니다.
5. [누락이 있는 출력](regression-output.json)은 합계가 맞지만 재고 0인 행이 없습니다.
6. 저장소 루트에서 `python3 examples/inventory/check.py`를 실행합니다. Python 표준 라이브러리만 필요합니다.

| ID | 요구사항 | 기준 결과물 | 기존 출력 예시 | 후보 출력 예시 | 누락 출력 |
| --- | --- | --- | --- | --- | --- |
| R1 | 모든 행·순서·품목명·수량·재고 0인 행 보존 | 통과 | 통과 | 통과 | 실패 |
| R2 | 합계가 원본 수량의 합과 일치 | 통과 | 통과 | 통과 | 통과 |
| R3 | JSON items와 정수 total, 각 항목의 item과 정수 available | 통과 | 통과 | 통과 | 통과 |
| R4 | 입력 누락·오류를 추측하지 않고 수정을 요청 | 미검증 | 미검증 | 미검증 | 미검증 |

검사 코드는 이 파일들의 R1~R3을 확인하며, 원본의 품목명 누락·음수·정수가 아닌 수량을 거부합니다. Python이 잘못된 데이터를 거부한다고 에이전트가 적절히 질문한다는 뜻은 아닙니다(R4).

## 로컬 검사 기록

2026-10-08에 `python3 examples/inventory/check.py`로 예시와 의도적 행 누락·수량 변조·중복 행·잘못된 합계·입력 오류의 예상 판정을 확인했습니다. 현재 파일은 같은 명령으로 재검증할 수 있습니다. 예상과 다른 통과·실패가 있으면 종료 코드가 0이 아닙니다.

## 결정

줄인 지침은 **후보로 보관**합니다. 문서 대조에서는 요구사항을 유지하고, 작성된 출력 예시는 R1~R3을 통과합니다. 하지만 그 지침이 해당 결과를 생성한다는 증거는 아닙니다. 실제 실행과 필요한 사람 판단이 확보되기 전에는 기존 버전을 유지합니다. 행 누락 출력은 합계가 맞아도 기각합니다.

실제로 시험하려면 두 버전을 각각 새 컨텍스트에서 기존 성공 입력과 새 입력으로 실행합니다. 결과물을 예시와 별도로 저장하고 `check.py SOURCE.csv OUTPUT.json`으로 검사합니다. 잘못된 입력에서 수정을 요청하는지도 확인합니다. [평가 기준 기록](../../evals/acceptance-record.ko.md)에 모델·커밋·입력·결과물·결정을 남깁니다. 이 예제로 시간이나 토큰 절감을 측정하지 않았습니다.
