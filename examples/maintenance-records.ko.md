# 실제 유지보수 기록과 한계

[English](maintenance-records.md)

Skilloom에 이미 공개한 저자의 실제 유지보수 요약입니다. 새 실험 결과가 아닙니다. 공개 근거는 [최초 기록 e26e180](https://github.com/boaz-hwang/skilloom/commit/e26e180)과 [회의록 기록 정정 9199860](https://github.com/boaz-hwang/skilloom/commit/9199860)입니다. 이 커밋은 공개한 설명을 확인하는 근거이며, 독립적으로 재현할 수 있는 실험 자료는 아닙니다. 비공개 원문과 전체 실행 기록은 포함하지 않습니다.

## 위키 통합: 줄인 뒤 누락을 발견

스킬 6개를 5개로 합쳤습니다. SKILL.md는 229줄에서 128줄로 줄었고 새 참조 파일 2개에 27줄을 추가했습니다. 삭제한 내용 상당수는 공통 검토 참조나 코드로 옮겼습니다. 폴더 접근 실패를 클리핑 0건으로 세지 않고 오류로 처리하고, 필수 원천과 항목별 기존 위키 대조를 확인하는 조사 기록 검사 및 테스트 12개를 추가했습니다.

이후 대조에서 요구사항 세 가지가 빠진 것을 발견했습니다.

1. update의 제안과 계약, 교육용 설계와 현재 운영 규칙 구분.
2. lint의 아직 연결하지 않은 원문 경로 존재 검사.
3. ingest의 새 원문이 기존 주장을 어떻게 바꿨는지 보고하는 항목.

클리핑 1회 10건 상한과 고정 주장·페이지 수는 의도적으로 삭제했습니다. 의도한 제거와 놓친 누락은 다른 결정입니다. 이 기록은 전체 요구사항 보존이나 성능 개선을 입증하지 않으며 줄 수도 전체 패키지 크기가 아닙니다. 누락된 요구사항이 이후 복구됐는지도 이 기록만으로 확인할 수 없습니다.

## 회의록: 무엇을 기준으로 좋아졌다고 판단했나?

처음 distill로 만든 스킬은 69줄, 내용 검사 스크립트는 79줄이었습니다. 이후 evolve로 결론과 판단 사항을 먼저 두기, 미확정 도표 구조는 초안으로 표시하기, 반복 환각이 여러 구간에 걸치면 더 강한 모델로 전체 재전사하기를 추가했습니다. 후보는 자체 비교에서 이겼지만 승인한 보고서 형식에서 벗어났습니다. 앞의 두 규칙은 8분 뒤 되돌리고 재전사 규칙만 남겼습니다.

| 구분할 항목 | 이 기록에서 확인할 수 있는 내용 |
| --- | --- |
| 승인한 결과 | 기존 보고서 형식이 승인돼 있었음. 비공개 결과물은 공개하지 않음 |
| 기존 요구사항 | 내용과 함께 승인 형식을 유지해야 했음. 전체 요구사항 목록은 공개돼 있지 않음 |
| 이번 변경 목표 | 이후 실행의 피드백을 반영. 이 피드백으로 기존 승인 형식을 대체할 수는 없음 |
| 비교의 문제 | 승인 결과물 대신 같은 세션의 피드백으로 후보를 평가 |
| 결정 | 기존 형식 유지. 재전사 규칙만 반영 |

되돌림은 저자가 형식 변경을 기각했다는 근거이며, 남은 모든 동작을 벤치마크했다는 근거는 아닙니다. 다음 비교에서는 승인한 결과물·유지할 요구사항·변경 목표를 먼저 구분합니다. [평가 기준 기록](../evals/acceptance-record.ko.md)을 사용할 수 있습니다.
